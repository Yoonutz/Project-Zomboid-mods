TwoManCrew's `media/ui/*.png` icons are **generated**, not hand-drawn assets. The source of
truth is `two-man-crew/make-icons.py`: each icon is a 16x16 character grid, one char per
pixel, upscaled 3x by nearest neighbour to the 48x48 variant. It writes RGBA PNGs with a
minimal built-in writer, so it needs no Pillow or any other dependency.

The palette is sampled from the original `TwoManCrew_Journal.png` so every icon reads as one
set: outline `#1A140F`, brass `#DAA238`/`#F0C874`/`#BA8E3E`, steel `#5C6878`/`#3E4856`.

**Why:** the alternative is binary assets nobody can diff or safely tweak. A grid edit is
reviewable in a normal diff, and the run is reproducible - regenerating from a different
working directory produced byte-identical files.

**How to apply:**

- Change an icon by editing its grid in `make-icons.py`, then `python two-man-crew/make-icons.py`.
  Never edit the PNGs directly; the next run overwrites them.
- The script resolves its output path from `__file__`, so it can be run from anywhere.
- **Verify shapes by ASCII-rendering the result, not by trusting the grid.** Two real defects
  only showed up that way: brass ruled lines on a brass book page vanished at 16px (contrast
  at this size has to come from the darkest palette colour), and two adjacent hard hats merged
  into one blob when their brims touched (the gap between shapes is what carries the meaning).
- Also check the pixels are not blank, per [[pz-vanilla-source-is-the-api-reference]] - a
  single-value luminance range means no shading and a blank-looking icon.
